
# 📘 Convenção de Commits

Utilize o padrão abaixo para manter o histórico de commits organizado e padronizado.

Formato:
```
<tag + emoji>: descrição da mudança no imperativo
```

---

## 📋 Tabela de Referência

| Tag + Emoji     | Quando usar                                                                 |
|-----------------|------------------------------------------------------------------------------|
| `feat ✨:`       | Nova funcionalidade ou melhoria que impacta o usuário                       |
| `fix 🐛:`        | Correção de bug                                                             |
| `chore 🧹:`      | Tarefa de manutenção (não afeta o comportamento da aplicação)              |
| `docs 📝:`       | Alterações na documentação                                                  |
| `style 💄:`      | Alterações visuais ou de formatação (sem alterar lógica)                   |
| `refactor 🔨:`   | Refatoração de código (sem mudar o comportamento da aplicação)             |
| `test 🧪:`       | Adição ou modificação de testes                                             |
| `perf ⚡:`       | Melhorias de performance                                                    |
| `ci 🤖:`         | Configuração de CI/CD ou scripts de automação                              |
| `build 🏗️:`      | Mudanças relacionadas à build ou dependências                              |
| `revert ⏪:`      | Reversão de um commit                                                       |
| `release 🚀:`    | Criação de uma nova versão ou publicação                                   |

---

## ✅ Exemplos válidos

- `feat ✨: add user registration screen`
- `fix 🐛: fix email validation error`
- `chore 🧹: organize project structure files`
- `docs 📝: update README with setup instructions`

---

> 💡 Dica: mantenha o texto da descrição curto, claro e no modo imperativo. Ex: "add", "update", "remove", "fix" etc.
